# 00 · RAG 入门（给第一次接触的同学）

这篇用大白话讲清楚本项目用到的核心概念，读完大概 5 分钟。**看不懂术语没关系，先建立画面感。**

## 1. 什么是 RAG

RAG = **Retrieval-Augmented Generation（检索增强生成）**。

一句话：**让大模型（LLM）在回答前，先从一个"资料库"里把相关资料找出来，再基于这些资料回答。**

类比：考试允许开卷。LLM 是那个记忆力很好但不知道"这本书里写了什么"的考生，RAG 就是帮它翻书、找到相关段落、再作答的过程。

为什么需要 RAG？因为模型的知识有截止日期、可能记错，而金融条款/法规/年报这类内容**必须依据原文**——不能凭印象答。

## 2. 为什么不能把整本书塞给模型

三个原因：

1. **上下文长度有限**：模型一次能"看"的文本有上限；
2. **贵**：输入内容越多，Token 花费越高（Token 见下）；
3. **噪声**：资料塞得越多，模型越容易被无关信息干扰，反而答错。

所以正确的姿势是：**先精准找到相关的几段，再给模型看这几段**。

## 3. Token 是什么

Token 是模型处理文本的最小单位，可以粗浅理解成"半个词/一个汉字左右"。模型按 Token 计费，也是本项目 `Token 全程记账` 的由来。

## 4. 分块（Chunking）

长文档不能整篇检索，先切成**小块**，每块几百字、带标题路径（`header_path`），类似"带书签的段落"。

本项目的分块规则（`data_processing/chunker_md.py`）：

- 按标题层级切（`第一章 > 第一条`）；
- 表格整块保留，不拆散；
- 控制每块大小（目标 350 token）；
- 太短的块与相邻块合并。

为什么要保留标题路径？因为检索到"第一章 保险责任 > 第一条 身故保险金"时，模型知道这段话出自哪里，引用更可靠。

## 5. BM25 是什么（本项目的主力检索）

BM25 是一种**关键词打分**算法：给"查询词"和"文档片段"算一个相关度分数。

两个直觉规则：

- 词出现的片段更相关；
- **稀有词**比常见词更有区分度（"身故保险金"比"的/和/是"重要得多）。

它不需要调用任何大模型，**零成本、离线可用**，所以是参赛方案的主力。

本项目对它做了增强（`retrieval/bm25_retriever.py`）：

- 用 jieba 做中文分词；
- 字符 Bigram 捕获"发行规模上限"这类连续短语；
- 精确子串加成：查询词原样出现在原文里额外加分。

## 6. 向量检索是什么（对比概念）

BM25 看"字面重合"，向量检索看"意思相近"。

做法：把文本用 embedding 模型变成一串数字（向量），意思相近的文本向量也相近，然后按距离找最相关的。

优点：能处理"同义词/换个说法"；缺点：要调模型、耗资源。

本项目的最终提交用 BM25，向量检索保留在 `retrieval/` 作为实验路径——**先想清楚"够用吗"，再决定要不要上更重的手段**，这是很实用的工程判断。

## 7. Rerank 是什么

检索先召回一批候选（可能 100 条），再用更强的模型**精排**，把最相关的几条排到最前。

类比：海选（粗筛）→ 复试（精排）。

## 8. F1 是什么（怎么判断"检索得好不好"）

F1 是"预测结果"和"正确答案"的重合度指标，综合了：

- **Precision（精确率）**：预测的结果里，多少是真正正确的；
- **Recall（召回率）**：正确的答案里，多少被预测到了。

F1 = 两者的调和平均，越高越好。只猜对的少数几条 → Recall 低；什么都预测 → Precision 低。所以 F1 惩罚"又少又杂"。

本项目用 Macro F1：先算每道题的 F1，再对所有题取平均。

## 9. Agentic RAG 是什么（本项目的进阶点）

传统 RAG：问题 → 直接检索 → 回答。

Agentic RAG：**让 LLM 先当"指挥官"**——

1. 先理解问题：这是什么类型的题？涉及哪几份文档？
2. 制定检索计划：每个选项/每个计算点分别查什么；
3. 调用检索工具（BM25）拿证据；
4. 把证据压缩成关键信息；
5. 基于证据作答，并给出引用来源。

本项目 `agent/` 目录就是这个五阶段流程的代码实现，核心思想是：**检索不是一次性的，而是由 LLM 规划和校验的闭环**。

## 10. 建议的阅读顺序

```text
1. 跑通 examples/rag_mini_demo.py（30 秒，感受分块→索引→检索）
2. 读本文档，建立概念
3. 读 docs/03-数据准备与分块.md（数据怎么变成小块）
4. 读 docs/04-检索系统.md（BM25 原理）
5. 读 docs/05-Agent流水线.md（完整五阶段流程）
6. 有 API Key 后跑 scripts/run_agent.py 看真实效果
```
