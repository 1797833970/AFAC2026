# 03 · 数据准备与分块

原始金融文档是 PDF / TXT / HTML 混合格式，不能直接喂给检索系统。本项目把它变成**结构化的分块（chunk）**，每一步都有独立模块，可以单独调试。

## 3.1 数据流水线总览

```text
data/raw/raw/<领域>/           原始文件（PDF / TXT / HTML）
        │
        ├── mineru.py ────────────────► data/processed_md/*.md
        │     (MinerU API：PDF 识别、表格、公式 → Markdown)
        │
        ├── document_parser.py ──────► data/processed/*.json
        │     (pdfplumber：章节树 + 平坦段落)
        │
        └── chunker_md.py ───────────► data/chunks/<领域>/*.json
              (Markdown/TXT → 语义分块)
                    │
                    └── scripts/split_chunks.py（可选二次切分）
                                │
                                ▼
                    data/chunks/all_chunks.json
```

## 3.2 原始数据目录结构

```text
data/raw/raw/
├── insurance/              # 保险条款（PDF）
├── regulatory/
│   ├── html/               # 监管法规 HTML
│   ├── attachments/        # 附件 PDF
│   └── txt/                # 清洗后的 TXT（如 strict_v3_*.txt）
├── financial_contracts/    # 金融合同（PDF）
├── financial_reports/      # 上市公司年报（PDF）
└── research/               # 行业研报（PDF）
```

> 官方数据请从赛题页面下载后放入 `data/raw/raw/`。该目录被 `.gitignore` 排除，不进仓库。

## 3.3 两条解析路径

### MinerU：PDF → Markdown（推荐用于图文混排文档）

`data_processing/mineru.py` 调用 MinerU 在线服务，把 PDF 转成 Markdown，能较好地保留表格与公式结构。

```bash
python -m data_processing.mineru check       # 校验文档映射
python -m data_processing.mineru --limit 3   # 试跑前 3 个
python -m data_processing.mineru             # 全量处理（需要 MINERU_TOKEN）
```

### pdfplumber：PDF → 章节树（本地解析）

`data_processing/document_parser.py` 在本地用 pdfplumber 按标题层级构建树形结构，适合纯文本年报。

```bash
python -m data_processing.document_parser
```

## 3.4 分块引擎（核心）

`data_processing/chunker_md.py` 是整个预处理的关键，完整规则见 `data_processing/chunks_rules.md`。设计目标：

1. **保留标题层级**：每个 chunk 记录 `header_path`，让 LLM 知道证据来自哪一章哪一条。
2. **表格原子化**：`<table>` 转成 Markdown 管道表，一整块打包，不拆散。
3. **Token 可控**：目标 350 token，最小 100、最大 400。
4. **自动识别标题约定**：不同文档的编号规则不同（中文编号 vs 阿拉伯编号），自动检测后选择对应规则。

### 标题处理

分块时维护一个"层级栈"：

```text
标题行 ──► 判断类型（阿拉伯编号 / 中文编号 / 无编号弱标题）
   │
   ▼
入栈 ──► 记录 header_path（如 "第一章 > 第一条"）
   │
   ▼
同级合并 ──► 相邻同 rank 小节合并，减少碎片
```

### 为什么分块参数重要

块太大：检索精度下降（一个 chunk 里无关信息太多），压缩成本高。
块太小：证据被切断，召回后上下文不完整。

本项目最终采用"中等粒度 + 二次切分"：

```bash
# 预览（不改文件）
python scripts/split_chunks.py

# 确认无误后执行（把 >350 token 的块按语义边界切成 200-400 的子块）
python scripts/split_chunks.py --apply
```

## 3.5 数据产物与复现

所有产物都能重新生成，因此不入仓库：

| 目录 | 内容 | 生成方式 |
|------|------|----------|
| `data/processed_md/` | MinerU 输出的 Markdown | `python -m data_processing.mineru` |
| `data/processed/` | 章节树 JSON | `python -m data_processing.document_parser` |
| `data/chunks/` | 分块 JSON | chunker_md / split_chunks |
| `full_text/` | 按领域导出的全文 | `python scripts/export_fulltext.py` |

全文导出便于人工通读、排查某句话在哪份文档里：

```bash
python scripts/export_fulltext.py --domains insurance
```
