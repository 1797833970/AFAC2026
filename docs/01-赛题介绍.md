# 01 · 赛题介绍

## 1.1 赛道背景

AFAC2026 赛道四的主题是**金融长文本 Agent 的动态记忆压缩与高效问答**。赛题给定一批真实金融文档（保险条款、监管法规、金融合同、上市公司年报、行业研报），参赛者需要在**不修改基座模型参数**的前提下，设计 Agent 层面的策略，让模型基于长文档准确作答，同时控制推理过程中的 Token 消耗。

这本质上是一个 **RAG + Agent 编排**问题：文档太长放不进上下文，就得分块、检索、压缩、再作答。

## 1.2 五类金融文本

| 领域 | 文档类型 | A 组题数 | B 组题数 |
|------|----------|---------|---------|
| insurance | 保险条款 | 20 | 20 |
| regulatory | 监管法规 | 20 | 20 |
| financial_contracts | 金融合同 | 20 | 20 |
| financial_reports | 财务报表 | 20 | 20 |
| research | 行业研报 | 20 | 20 |

每道题会给定 `doc_ids`（相关文档列表），要求从这些文档中找证据作答。

## 1.3 题型与答案格式

| 题型 | 答案要求 | 示例 |
|------|----------|------|
| 单选题（mcq） | 唯一大写字母 | `B` |
| 多选题（multi） | 按字母序连续书写 | `ACD` |
| 判断题（tf） | `A`=正确 / `B`=错误 | `A` |
| 计算题 | 数值/百分比/日期等，按要求格式化 | `333.20`、`12.34%`、`2026年1月1日` |
| 抽取题 | 按题目要求输出文本片段 | 见题目说明 |

多值题（如"按顺序填写四个数"）用分号分隔，提交时分别填入 `answer_1`~`answer_4`。

## 1.4 评分公式

```text
FinalScore = 100 × Accuracy × (0.7 + 0.3 × TokenScore)
TokenScore = max(0, min(1, (5,000,000 - TotalTokens) / 5,000,000))
```

要点：

- **准确率占主体**：每道题要么对要么错，答案格式错误直接判错。
- **Token 效率影响最多 30%**：总 Token 越少，TokenScore 越高；500 万 Token 是预算上限。
- 因此策略上要"先保准确率，再省 Token"：检索不要漏证据（漏了必错），但也不要无脑塞满上下文。

## 1.5 关键约束

- 不得修改基座模型参数（不允许微调）。
- 必须使用赛题指定的官方模型，不得用其他开源/闭源模型顶替。
- 总 Token 预算 5,000,000，超预算的提交会损失 TokenScore。

## 1.6 本项目的解题思路

一句话：**用 Agent 四步流水线把"大海捞针"变成"精准取证"**。

```text
文档预处理（PDF → Markdown → 分块）
        ↓
BM25 索引（离线构建，本地检索零 API 成本）
        ↓
Step 1 检索规划：LLM 读懂题目，拆解每个选项/计算点，生成检索计划
        ↓
Step 2 检索执行：按计划在目标文档内 BM25 召回 Top-K
        ↓
Step 3 证据压缩：LLM 把原始片段压缩成"只留证据"的精简文本
        ↓
Step 4 综合作答：LLM 基于压缩证据输出答案（计算题先写代码后算数）
```
