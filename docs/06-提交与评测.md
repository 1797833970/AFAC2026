# 06 · 提交与评测

## 6.1 官方提交格式

提交文件是 CSV，**表头固定 8 列**：

```csv
qid,answer_1,answer_2,answer_3,answer_4,prompt_tokens,completion_tokens,total_tokens
```

规则：

- `qid` 必须与题目数据一致；
- 单答案题只填 `answer_1`；多值题按顺序填 `answer_1`~`answer_4`，其余留空；
- 三列 Token 必须为非负整数，且 `total_tokens = prompt_tokens + completion_tokens`；
- 表头之后必须有一行 `summary` 汇总：

```csv
summary,,,,,123456,789,124245
```

## 6.2 各题型答案格式

| 题型 | 要求 |
|------|------|
| 选择题/判断题 | 大写字母，多选题按 A-D 顺序连续书写（`ACD`） |
| 单位类计算题 | 只填数字，保留两位小数（`333.20`） |
| 百分数 | 必须带 `%`，保留两位小数（`12.34%`） |
| 日期 | 中文格式 `YYYY年M月D日`（`2026年1月1日`） |
| 文本类 | 完整文本，不加无关说明 |
| 排序类 | 用英文半角 `>`，前后无空格 |

答案格式错误会直接判错，**生成提交后务必做格式校验**。

## 6.3 本项目如何生成提交

```bash
python scripts/build_submission.py \
  --answers output/answers.json \
  --out output/submission.csv
```

脚本做的事：

1. 读取 `run_agent.py` 输出的答案（或手写 `{qid: answer}` 映射）；
2. 按题目类型把答案拆进 `answer_1`~`answer_4`；
3. 优先使用 Agent 记录的真实 token，缺失时按文本长度透明估算；
4. 写入官方 8 列格式 + summary 行；
5. 输出警告（空答案、选择题答案不是 A-D 等）并计算 TokenScore。

选项 `--with-reasoning` 会额外生成一份带 `reasoning` 列的审计 CSV，方便人工核对推理过程，但**正式提交不要带这一列**。

## 6.4 Token 估算与 TokenScore

官方评分：

```text
TokenScore = max(0, min(1, (5,000,000 - TotalTokens) / 5,000,000))
```

本项目对 Token 的态度：

- **优先保准确率**：检索必须覆盖证据，Token 节省不能以漏证据为代价；
- **压缩是省 Token 的正道**：Step 3 把长 chunk 压成证据摘要，比截断上下文划算得多；
- **估算要透明**：`build_submission.py` 的估算公式写死在代码里（中文约 0.5 token/字），用于本地估算；真实 token 以平台统计为准。

## 6.5 答案验证工作流

金融题最怕"看着对、实际错"。本项目在提交前对答案做了逐题核对：

- B 榜保险领域 20 题逐题对照条款原文的验证报告（计算过程 + 证据引用 + 结论），随最终提交保留在本地 `output/archive/`，**不进入公开仓库**（含答案）。
- 验证方法：对每道题先定位条款原文，再按原文重算，最后对照答案。

建议流程：

```text
Agent 出答案
   │
   ▼
导出证据（output/evidence/）
   │
   ▼
人工/LLM 逐题核对证据与计算
   │
   ▼
修正答案 → 重新 build_submission → 提交
```
