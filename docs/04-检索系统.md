# 04 · 检索系统

## 4.1 设计取舍：为什么最终用 BM25

赛题里每道题都给了 `doc_ids`（候选文档列表），范围已经很小。这种情况下：

- **向量检索的优势不明显**：候选文档就几篇，语义召回带来的收益有限；
- **BM25 的优势很直接**：金融术语精确匹配（"身故保险金""发行规模上限"），零 API 调用、零延迟、可离线。

因此**最终提交用的是增强版 BM25**；Dense 向量与混合检索作为实验路径保留在 `retrieval/` 中（见 4.4），但没有进入最终方案。

## 4.2 增强 BM25：三重打分

`retrieval/bm25_retriever.py` 在标准 BM25 之上加了两个针对中文金融文本的增强：

```text
Score = BM25 基础分
      + 0.30 × 字符 Bigram 重叠分
      + 0.25 × 精确子串加成
```

### ① BM25 基础分

用 `jieba.cut_for_search` 细粒度分词（"保险公司"会被切成更小的词），按经典 BM25 公式计算：

```text
K1 = 1.5,  B = 0.75
score = Σ IDF(t) × [tf·(K1+1) / (tf + K1·(1 - B + B·dl/avgdl))]
```

### ② 字符 Bigram 重叠分

中文短语（如"发行规模上限"）分词后可能被打散，直接字级两两组合成 Bigram 集合，与查询的 Bigram 集合求交集，捕获连续短语。

### ③ 精确子串加成

查询中的关键词如果在原文中作为子串出现，说明是"原汁原味"的术语，额外加分。

### 索引结构

构建时持久化为 `data/index/bm25_index.pkl`，包含：

- `chunks`：原文分块
- `tokenized_docs`：jieba 分词结果
- `bigram_docs`：字符 Bigram 集合
- `inverted`：倒排索引（term → [(doc_idx, tf)]）
- `idf` / `avgdl` / `doc_freq`

搜索时**只遍历包含查询词的候选文档**，不扫全库，速度很快。

## 4.3 使用方式

```bash
# 构建索引（首次）
python scripts/build_index.py build

# 强制重建
python scripts/build_index.py build --force

# 检索测试
python scripts/build_index.py search "身故保险金如何计算" --top-k 5

# 索引统计
python scripts/build_index.py info
```

代码中使用：

```python
from retrieval.bm25_retriever import BM25Retriever

retriever = BM25Retriever.load()
hits = retriever.search("身故保险金", doc_ids={"insurance_1"}, top_k=3)
```

`doc_ids` 支持前缀匹配（如 `strict_v3_009` 可匹配 `strict_v3_009_xxx`），方便按文档组检索。
