# Chunk 分块规则

## 1. 标题识别

### 1.1 触发条件
- 所有 `#{1,6} ` 开头的行识别为标题
- 空白标题（`# ` 后无内容）→ 当作文本，不建 section

### 1.2 标题分类

两套 rank 规则，程序启动时自动检测文档使用哪种约定：

**检测逻辑**：扫描全文标题。若前 3 个编号标题全是阿拉伯（`1.` / `1.1.` / `1、` 等）且无中文编号（`第X节` / `一、` 等）→ 约定 B；否则 → 约定 A。

#### 约定 A（中文在上）— 金融合同 / 年报 / 监管文件

| 模式 | rank | type |
|------|------|------|
| `第X章` | 1 | T_CHINESE |
| `第X节` | 2 | T_CHINESE |
| `第X条` | 3 | T_CHINESE |
| `一、` `一．` `一.` `一）` `一)` | 4 | T_CHINESE |
| `（一）` | 5 | T_CHINESE |
| `1.` `1、` `1．` | 6 | T_ARABIC |
| `1.1.` `1）` `1)` `（1）` `(1)` | 7 | — |
| `1.1.1.` | 8 | T_ARABIC |
| `1.1.1.1.` | 9 | T_ARABIC |
| 其他 | — | T_PLAIN |

层级示例：`第一节(2) → 一、(4) → （一）(5) → 1、(6) → （1）(7)`

#### 约定 B（阿拉伯在上）— 保险条款 / CMB 年报 / 部分研报

| 模式 | rank | type |
|------|------|------|
| `第X章` | 1 | T_CHINESE |
| `第X节` | 2 | T_CHINESE |
| `第X条` | 3 | T_CHINESE |
| `1.` | 4 | T_ARABIC |
| `1.1.` | 5 | T_ARABIC |
| `1.1.1.` | 6 | T_ARABIC |
| `1.1.1.1.` | 7 | T_ARABIC |
| `1、` `1．` | 8 | T_ARABIC |
| `1）` `1)` | 9 | T_ARABIC |
| `一、` `一．` `一.` `一）` `一)` | 10 | T_CHINESE |
| `（一）` | 11 | T_CHINESE |
| `（1）` `(1)` | 12 | T_CHINESE |
| 其他 | — | T_PLAIN |

层级示例：`1.(4) → 1.1.(5) → 1.1.1.(6) → 一、(10) → （一）(11)`

**已知局限**：同一文档内，相同 pattern 出现在不同层级时（如保险条款中 `1.` 既是顶层章节又是子要点），固定 rank 无法区分，按顶层处理。

> rank 越大越深，None 表示 T_PLAIN。pipeline 以第一条匹配为准，故多段式阿拉伯编号（`1.1.1.`）必须在单段式（`1.`）之前。

### 1.3 弱标题

匹配以下关键词的标题标记为 `is_weak=True`（匹配前去半角/全角空格）：

`目录 | 释义 | 备查文件 | 附件 | 摘要 | 声明 | TOC | abstract | summary | disclaimer | declaration | glossary | appendix`

弱标题行为：
- **hp**：直接写自己的 title，不拼接栈路径
- **栈**：单独追加，不与前后 PLAIN 合并
- **合并**：不参与任何 chunk 合并（同级/PLAIN 均跳过）
- **正文**：title 只在 hp 中，不重复写入 text（hp 非空，不会触发 prepend）

---

## 2. 层级栈

栈元素 `(title, rank, is_weak)`。rank 越大越深，None 表示 PLAIN。

### 2.1 PLAIN（rank=None, 非弱）
- 追加到栈顶。若栈顶也是非弱 PLAIN → 合并为 `前 + 后`
- **栈全为 PLAIN 时**：
  - 单个 PLAIN → hp = 自己的 title
  - 多个连续 PLAIN → hp = ""
- **栈中有编号标题时**：PLAIN 不进 hp，标题保留在正文原位置（hp 仅由编号标题 `>` 串联）
- hp 空时，标题写回正文首行（避免信息丢失）

### 2.2 弱标题（is_weak=True）
- 栈：单独追加，不合并
- hp：直接等于自己的 title

### 2.3 编号标题（rank=1~12）
- 先弹出栈顶所有 PLAIN（含 weak）
- 再弹出所有 `rank >= 当前 rank` 的编号标题
- 追加当前标题
- hp = 栈中 title 用 ` > ` 连接

---

## 3. 同级合并

> 反复扫描至稳定。仅合并相邻、同 rank、同父、seq 连续、token 允许的编号标题。

### 3.1 合并条件
- 双方非弱
- 同 rank
- 同父路径（`_parent(hp)` 一致）
- seq 连续（`b.seq == a.last_seq + 1`）
- 合并后 token ≤ MAX_T(400)

### 3.2 合并行为
- 文本合并到第一个 chunk
- labels 拼接：`a.labels.extend(b.labels)`
- hp 末级更新为 `label1 + label2 + label3`（用 `_short()` 提取简短标识）
  - ARABIC：用 prefix（如 `1.1`）
  - CHINESE：提取编号部分（`一、发行人` → `一`，`（一）利率` → `（一）`）

### 3.3 全覆盖简化
合并后，检查"父路径下是否还有**其他**同 rank 非弱 section"。

若**没有**且父路径非空 → hp 提升为父路径，rank/type/seq/labels 更新为父层对应值。

简化后 section 可继续参与下一轮扫描的同级合并，实现自底向上逐层收敛。

示例：
```
（一）+(二)+(三)+(四)+(五) → 全覆盖 → hp="一、与本期债券相关的投资风险"
一、+ 二、 → 全覆盖 → hp="第一节 风险提示及说明"
```

---

## 4. PLAIN 合并

> 同级合并完成后，相邻非弱 T_PLAIN section 可合并。

- 合并后 hp = ""
- 若第一个 section 的标题原本只在 hp 中（hp 原非空）→ 合并时补回 text 首行

---

## 5. 正文处理

### 5.1 图片
- 从正文提取 `![](...)`，存入 `images` 字段
- 不计入 token，同一 section 所有 chunk 共享

### 5.2 表格
- `<table>...</table>` 转为 Markdown 表格格式（`|...|`），**保留在正文中**
- 表格作为**原子段落**，不跨 chunk 拆分
- 若表格超过 MAX_T(400)，**仅在行边界处拆分**，每个分片保留表头行
- 表格 token 正常计入

### 5.3 分块
1. 表格块提取为原子段落（`_table_aware_split`）
2. 按空行拆段
3. 超长段按句号/分号切句（无句号按字符硬切）；超长表格按行拆分
4. 贪心打包至 MAX_T(400)，表格作为整体优先打包（目标块大小 TARGET=350）
5. section 内 token < MIN_T(100) 的短 chunk 向前合并

---

## 6. 输出

- `chunk_id` = `{doc_id}_{1..N}`
- 字段：`chunk_id, doc_id, header_path, text, tokens`
- 有附加数据时：`images, tables`
